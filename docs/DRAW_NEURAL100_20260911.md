# Draw corrections with the selected network at blend 100

This isolated candidate follows the user's request to optimize further before
another long comparison. The draw-only blend75 patch's +5 =11 -4 quick result
was inconclusive; its long run was stopped and is not pooled into this test.
The previously released neural blend75 engine remains the upload recommendation
until a replacement earns promotion.

The sole additional runtime change from `draw-fix-fast` is `HALFKP_BLEND = 100`.
It uses the selected anneal128 weights. Classical evaluation still handles seven
or fewer pieces and either bare king, and the mop-up helper remains applied.
The book, all 96 tablebases, feature encoding, quantization and weights are
unchanged. No data was downloaded and no additional training was performed.

## Why this candidate

The earlier blend100 trial used a different refined checkpoint; it did not test
the selected anneal128 checkpoint with these draw corrections. A held-out static
probe on 18,799 FENs found lower errors with the neural route in every piece band.
Among 1,777 positions with 8–12 pieces, MSE was 0.031829 at blend0, 0.020216 at
blend75 and 0.019506 at blend100. Reducing neural influence was not supported.
Static fitting is a selection screen, not playing-strength evidence.

A repeated isolated-core depth5 benchmark across ten positions took 4.690 s at
blend75 and 3.601 s at blend100, with 128,397 and 99,393 nodes respectively.
Node throughput was 27.38k versus 27.60k NPS, so the earlier approximate 10%
NPS advantage was not reproduced at that magnitude. Different evaluations
change the searched trees; the elapsed-time difference is not proof of a
general speed or strength gain. An earlier integration timing overlapped a
diagnostic on CPU4; use the separate CPU6 throughput record for timing.

- The 10,000-position integer reference proof remains applicable: the exact
  weights and inference source hashes are unchanged.
- The actual extracted ZIP passes source/asset, init, memory and legal-move
  checks: 49,470,039 unzipped bytes, 107 files, 12.775 s init and peak working set
  227,225,600 bytes. ZIP SHA256:
  `e5ae96ae1ff4338fec11af8039e5607e3d8475ba0e5b360ef9c4967cdaba10c5`.

Fresh-cache, history-preserving probes of 19 earlier opportunities found zero
repeated choices with draw-fix-fast versus nine with the neural predecessor.
Two separately played development positions then converted with this blend100
candidate: the recorded queen advantage mated in 31 new plies, and the rook/pawn
advantage mated in 75. The predecessor repeated to draws after four and 77 plies.
Both builds used the same diagnostic setup and plain classical opponent.
These selected known cases use fixed per-move inputs, fresh caches and disabled
background work. They are conversion regressions, not independent fair-clock
matches, proof that every earlier advantage was winning, or rating evidence.

The first integration-tool invocation used the CPU environment that lacks the
controller-only psutil package. It failed before testing the engine; the log is
retained. The successful rerun used the separate controller environment. Actual
protocol agents continue to use the competition-pinned CPU interpreter.
